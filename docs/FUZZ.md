# Fuzzing

The repository has two fuzzing front ends: standalone AFL-mode harnesses and
libFuzzer harnesses. Both use the same `libks/fuzzer.h` callbacks.

## American Fuzzy Lop (AFL)

1. Configure and compile the binary.

   ```sh
   ./configure --pedantic
   make clean
   AFL_USE_ASAN=1 AFL_USE_UBSAN=1 CC=afl-cc make
   ```

2. Copy the binary to a safe place.

   ```sh
   cp knfmt /tmp
   ```

3. Create directories.

   ```sh
   mkdir -p fuzz/{i,o}
   ```

4. It is often of interest to exercise the latest source code changes by
   using the latest test cases as the corpus.

   ```sh
   git log --name-status tests/*.[ch] |
   sed -n 's/^A[[:space:]][[:space:]]*//p' |
   head -15 |
   xargs -I {} cp {} fuzz/i
   ```

5. Start one or many instances of afl-fuzz.

   ```sh
   afl-fuzz -i fuzz/i -o fuzz/o -M f0 /tmp/knfmt -s
   afl-fuzz -i fuzz/i -o fuzz/o -S f1 /tmp/knfmt -s
   ```

## libFuzzer harnesses

`--fuzz llvm` selects the libFuzzer entry points in `libks/fuzzer.h` and
defines `FUZZER_LLVM` in `config.h`. Without that option the harnesses build
in AFL mode and read one input from standard input.

```sh
CC=clang ./configure --fuzz llvm
make fuzz-parse fuzz-style
./fuzz-parse -dict=parse.dict <seed-dir>
./fuzz-style -dict=style.dict <seed-dir>
```

- `fuzz-parse` formats each input three times and requires the last two
  results to be byte-identical. The first pass may normalize the input.
- `fuzz-style` parses a `.clang-format` document. A `BasedOnStyle` value can
  make it execute the external `clang-format` helper.
- `parse.dict` is a hand-maintained C token dictionary. `style.dict` is
  generated by `make style.dict` from `fuzz-dict`.
- libFuzzer needs a C++ runtime at link time. If the default link fails, pass
  its directory in `LDFLAGS`, for example
  `LDFLAGS=-L/usr/lib/gcc/x86_64-linux-gnu/16`.

## Mutation driver

`tests/mutate.pl` drives a standalone AFL-mode harness and classifies
findings as `CRASH`, `TIMEOUT` or `SEMANTIC_*`. The semantic check uses the
independent oracle in `tests/semanticoracle.pl`.

```sh
perl tests/mutate.pl ./fuzz-parse 20000 crashes
```

The harness must enforce idempotence itself; `fuzz-parse` does so by trapping
when the last two passes differ. Findings are written below the output
directory. Minimize a finding before promoting it to a fixture, and add a
reproducer under `tests/` once the cause is understood.

## Corpora and regression promotion

- Accepted inputs are `tests/valid-*.c` and `tests/semantic-*.c`.
- Formatting regressions are `tests/repro-idempotence-*.c`, checked by
  `tests/idempotence.sh` in normal and `-s` mode.
- Inputs that are still known to be mishandled live in
  `tests/known-nonidempotent/`. `tests/known-nonidempotent.sh` fails when one
  of them starts passing, so the case is promoted rather than forgotten.
- `tests/semantic.sh` checks normal-mode token preservation independently of
  the formatter lexer.
